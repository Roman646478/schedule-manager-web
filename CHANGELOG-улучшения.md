# Отчёт об улучшениях проекта schedule-manager

Дата: 11.06.2026. Проведён аудит кода, затем по очереди исправлены найденные проблемы.
Все изменения покрыты проверками: **30/30 тестов проходят**, сервер проверен вживую
(логин, сессии, CSP-заголовки, отказ очистки с неверным паролем).

---

## 1. Безопасность

### Пароль очистки БД больше не захардкожен
Было: `RESET_PASSWORD: '2707'` открытым текстом в `src/utils/constants.js`.
Стало: bcrypt-хэш в `data/config.json` (поле `resetPasswordHash`). Старые конфиги
мигрируют автоматически при первом запуске. Дефолт задаётся через
`DEFAULT_RESET_PASSWORD` в `.env` — **смените его**.

- Изменены: `src/utils/constants.js`, `src/services/authService.js`
  (новые функции `verifyResetPassword`, `changeResetPassword`),
  `src/routes/schedule.js` (роут `/api/reset`), `.env.example`.

### Включён Content-Security-Policy
Было: `helmet({ contentSecurityPolicy: false })`.
Стало: строгий CSP — скрипты/стили/запросы только со своего origin,
`object-src 'none'`, `frame-ancestors 'none'`. Для этого инлайн-скрипт формы
входа вынесен из `login.html` в отдельный файл `public/js/login.js`.

- Изменены: `src/server.js`, `public/login.html`; создан `public/js/login.js`.

### Сессии в SQLite вместо MemoryStore
MemoryStore терял сессии при рестарте и тёк по памяти. Теперь сессии хранятся
в таблице `sessions` той же БД, просроченные удаляются фоновым таймером.

- Создан: `src/config/sessionStore.js`; изменён `src/server.js`.

### Прочее по безопасности
- Rate-limit логина: Map с попытками по IP теперь периодически чистится
  (раньше рос бесконечно). — `src/routes/auth.js`
- В продакшене (`NODE_ENV=production`): кука сессии получает флаг `secure`,
  включается `trust proxy` для корректного IP за обратным прокси. — `src/server.js`

## 2. Корректность

### Устранена гонка при переносе занятия (TOCTOU)
Было: валидация переноса выполнялась **до** транзакции, запись — внутри неё;
между ними другой запрос мог занять слот.
Стало: `moveLesson` выполняет валидацию и UPDATE внутри одной транзакции —
недопустимый перенос невозможен, частично применённых изменений не бывает.

- Изменён: `src/services/scheduleService.js`.

## 3. Производительность

### Оптимизирован `getMoveOptions`
Было: для каждого слота (недели × 6 дней × 4 пары) — полная фильтрация всех
занятий, O(слоты × занятия).
Стало: занятия один раз группируются в Map по ключу «день|пара|неделя», O(занятия).

- Изменён: `src/services/scheduleService.js`.

## 4. Архитектура и код

### Единый источник доменных констант
Дни недели, число пар и время пар дублировались в трёх местах (бэкенд,
admin.js, guest.js) — рассинхронизация была вопросом времени.
Теперь всё в одном UMD-модуле `public/js/shared-constants.js`: сервер берёт
его через `require`, страницы — через `<script>`. Менять время пар — только там.

- Создан: `public/js/shared-constants.js`; изменены: `src/utils/constants.js`,
  `public/js/admin.js`, `public/js/guest.js`, `public/admin.html`, `public/weekly.html`.

### ESLint + Prettier
Добавлены `eslint.config.js` (flat-конфиг, отдельные правила для Node и браузера),
`.prettierrc`, devDependencies и скрипты:

```
npm run lint     # проверка кода
npm run format   # автоформатирование
npm run check    # lint + тесты
```

Перед первым запуском: `npm install`.

### .gitignore
Исключены: `claude-memory-compiler/.venv/` и `__pycache__/` (чужое виртуальное
окружение Python — не часть сайта), `public/public_db.json` (генерируется публикацией).

### Актуализирован .claude-rules.md
Дерево структуры, список роутов и секция тестирования приведены к реальному
состоянию проекта; секция «миграция устаревшей структуры» закрыта как выполненная.

## 5. Тесты

- **Новый тест** `tests/services/moveLesson.db.test.js`: перенос в свободный слот
  применяется атомарно; перенос в занятый — отклоняется и не меняет БД.
- В api-тестах `BCRYPT_ROUNDS=4` — быстрые хэши вместо полной стоимости bcrypt.
- Итог: было 28 тестов, стало **30, все зелёные** (`npm test`).

## Что сделано НЕ было (сознательно)

1. **Проверка типа/оснащения аудитории при переносе** (требование CLAUDE.md,
   колонка `rooms.kind` уже есть) — пропущено по решению пользователя.
2. **Разбиение `public/js/admin.js` (~825 строк) на модули** — рефакторинг без
   возможности прокликать UI в браузере рискует сломать админку. Делать вместе
   с ручным тестированием.
3. **Редактирование времени пар через админку** — новая фича, а не ошибка.
   Сейчас время меняется в `public/js/shared-constants.js`.

## Рекомендации после обновления

1. Выполнить `npm install` (подтянет eslint/prettier).
2. Сменить пароли: админский и `DEFAULT_RESET_PASSWORD` (или удалить
   `data/config.json` — пересоздастся с новыми значениями из `.env`).
3. Открыть админку и прокликать основные сценарии: импорт, перенос пары,
   проверка ошибок, публикация, тёмная тема.
4. `npm run check` перед каждым значимым изменением.
