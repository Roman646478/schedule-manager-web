# schedule-manager

Веб-инструмент для работы с готовым расписанием вуза. На вход — HTML-экспорт
расписания (из 1С-подобной системы) в трёх представлениях: по **группам**, по
**преподавателям**, по **аудиториям**. Система собирает из них **единый источник
данных**, проверяет накладки и вместимость, позволяет переносить пары в свободные
окна и публиковать расписание для гостевого просмотра.

## Версии и веб-сборка

Текущий выпуск: **v0.4.0**. [Основные изменения](docs/releases/v0.4.0.md).
Каждый выпуск хранится в GitHub Releases с отдельным тегом `vX.Y.Z`,
описанием изменений, ZIP-архивом и файлом SHA-256.

`npm run build:web` создаёт `dist/schedule-manager-web-vX.Y.Z/` — серверное
веб-приложение без Windows-виджета и рабочих данных. После распаковки выполните
`npm ci --omit=dev` и `npm start`; требуется Node.js 22 или новее.
`npm run build` по-прежнему собирает полный комплект с виджетом.

Для следующего выпуска обновите версию в `package.json` и `package-lock.json`,
добавьте `docs/releases/vX.Y.Z.md`, обновите ссылку выше и выполните `npm run check`.
Сохраните изменения коммитом, создайте тег `vX.Y.Z` и отправьте коммит и тег
на GitHub. Workflow `Web release` соберёт архив и опубликует выпуск автоматически.
Уже опубликованные теги не переиспользуйте: исправления выпускаются новой версией.

## Возможности

- **Импорт** набора HTML-файлов (группы/аудитории/преподаватели) со сборкой
  единого источника и автоматической простановкой преподавателей.
- **Три согласованных представления** одного расписания (группа/преподаватель/
  аудитория) — это выборки из единой таблицы занятий, не копии.
- **Перенос пар** drag-and-drop: свободные окна (где свободны и группа, и
  преподаватель) подсвечиваются; если аудитория занята — предлагается список
  свободных аудиторий. Потоковое занятие переносится целиком.
- **Проверка ошибок**: накладки преподавателя/группы/аудитории, превышение
  вместимости, битые ссылки.
- **Настройка семестра** (осень/весна + даты начала/конца) → календарь дат: дата
  каждого дня = понедельник недели 1 + (неделя−1)×7 + смещение дня.
- **Недельный и семестровый** виды; **публикация** снимка для гостей.
- **Учётные записи кафедр**: администратор задаёт логин, пароль, кафедры и
  отдельные группы; сотрудник видит всё расписание, но меняет только занятия,
  все группы которых входят в его доступ.
- **Общий журнал переносов** с автором и адресной отменой конкретного действия.
  Сетевой повтор команды не выполняет перенос повторно.
- **Полная очистка БД** с подтверждением паролем.

## Запуск

```bash
npm install
npm start          # https://127.0.0.1  (порт 443; npm run dev — с автоперезапуском)
npm run build:full # полная версия в отдельной папке dist/schedule-manager-full-vX.Y.Z
npm run build:web  # веб-версия в отдельной папке dist/schedule-manager-web-vX.Y.Z
npm test           # юнит/интеграционные тесты (node --test)
npm run test:e2e   # браузерные smoke-сценарии (Playwright/Chromium)
npm run check      # линтер + оба набора тестов
```

Перед первым браузерным прогоном на новом компьютере выполните
`npx playwright install chromium`. E2E-сервер использует отдельную временную
базу и не открывает рабочий файл из `data/`.

Первый запуск создаёт `data/schedule.db` (расписание), `data/access.db`
(пользователи, права и сессии) и `data/config.json` (секреты и совместимость со
старыми установками). Учётка по умолчанию — `admin` / `admin`. Сменить пароль
можно прямо в админке (кнопка **«Сменить пароль»**) — пока он дефолтный, вверху
страницы висит предупреждение, а сервер пишет о нём в консоль при старте.

## HTTPS в локальной сети

По умолчанию сервер работает по HTTP — в общей сети логин и cookie сессии идут
открытым текстом. Для шифрования включите TLS (офлайн, без внешних CA):

```bash
npm run gen-cert   # самоподписанный сертификат → data/tls/{key,cert}.pem
npm start          # увидев сертификаты, сервер сам поднимется по HTTPS
```

`gen-cert` использует системный `openssl` и вписывает в сертификат все IP этой
машины (SAN), поэтому он подходит и для доступа по LAN-адресу. Браузер один раз
покажет предупреждение о самоподписанном сертификате — это ожидаемо.

Переменные окружения: `TLS_KEY_PATH`/`TLS_CERT_PATH` (свои пути к сертификату),
`HTTP_REDIRECT_PORT` (поднять доп. порт, редиректящий HTTP→HTTPS),
`HSTS_ENABLED=1` (включать **только** с доверенным сертификатом — с
самоподписанным HSTS закроет доступ).

## Использование

1. Открыть `/login.html`, войти (admin/admin).
2. В админке (`/admin.html`): задать **Настройку семестра**; **Загрузить** HTML-
   файлы расписания; при необходимости заполнить **Справочники** (ёмкость
   аудиторий, численность групп — для проверки вместимости).
3. Переносить пары перетаскиванием; проверять ошибки; **Опубликовать**.
4. Гостевой просмотр опубликованного расписания — `/weekly.html`.

Пользователей создаёт администратор кнопкой **«Пользователи»**. Права кафедры
добавляются ко вручную отмеченным группам. Поток со своей и чужой группой
остаётся целиком только для чтения. В видах преподавателя и аудитории чужие
занятия видны с замком. Гостевое редактирование окончательно отключено.

## Архитектура

```
src/
  server.js              # Express: helmet, сессии, статика, роуты, errorHandler
  config/database.js     # node:sqlite (WAL), схема расписания
  config/accessDatabase.js # отдельная БД пользователей, прав и сессий
  routes/                # auth, import, schedule, rooms — тонкие HTTP-обработчики
  middleware/            # auth (сессия), validation, errorHandler
  services/              # бизнес-логика:
    importService.js     #   сборка единого источника из 3 типов файлов
    conflictService.js   #   загрузка занятий + проверки (поверх validators)
    scheduleService.js   #   представления, перенос, опции переноса, публикация, сброс
    authService.js       #   bcrypt, вход и секрет сессии
    userService.js       #   пользователи, права кафедр/групп, аудит доступа
    settingsService.js   #   настройки (семестр)
    dbService.js         #   transaction, getOrCreate, clearAll
  parsers/htmlScheduleParser.js  # HTML → нормализованные занятия + подвал дисциплин
  utils/                 # validators (чистые проверки), calendar (даты семестра),
                         #   constants, helpers (декодирование, clean, groupBy)
public/                  # фронтенд: index/login/admin/weekly.html,
                         #   css/{theme,styles}.css, js/{api,theme,admin,guest}.js
tests/                   # parsers / services / utils / api
```

### Модель данных (единый источник)

- `lessons` — одна запись = занятие в конкретную неделю (день, пара, неделя,
  предмет, тип, teacher_id, room_id). Дата НЕ хранится — вычисляется из семестра.
- `lesson_groups` — связь занятие↔группы (M:N): потоковое занятие = одна запись
  `lessons` + несколько групп.
- `groups`/`rooms`/`teachers` — справочники (headcount/capacity заполняются вручную).
- `subjects` + `subject_teachers` — дисциплины из подвала и кандидаты-
  преподаватели по ролям (lecturer/other) для ручного выбора.
- `settings` — key-value (семестр: name/start/end).
- `move_actions` + `move_action_events` — адресные команды переноса, авторы,
  снимки до/после и события отмены.

Пользователи не входят в эту БД. Они хранятся в `access.db`; ручная привязка
группы использует стабильный `groups.access_uid`, поэтому удалённая группа не
передаёт права новой группе с тем же названием.

### Сборка единого источника (импорт, 3 прохода)

1. **Файлы групп** — база занятий + справочник дисциплин (подвал).
2. **Файлы аудиторий** — добор занятий, которых нет в базе.
3. **Файлы преподавателей** — простановка ФИО по совпадению слота.

Ключ слияния: `(день, пара, неделя) + аудитория + предмет`; группы аккумулируются
(потоки). Если преподаватель не определён файлом — остаётся список кандидатов из
подвала, отфильтрованный по виду занятия (лекция → лекторы, иначе → «другие»).

## Архив базы (версии)

Версия — снимок всей базы целиком (`data/archives/<дата_время>.db`), снятый
через `VACUUM INTO` прямо на работающем сервере. Примечание, дата и признаки
версии хранятся ВНУТРИ файла снимка (таблица `archive_meta`), поэтому файл
самодостаточен, а списку неоткуда рассинхронизироваться с папкой.

- Переключение подменяет файл базы целиком, поэтому применяется атомарно —
  частично применённого состояния не бывает.
- Перед переключением текущее состояние само уходит в версию с меткой «авто»
  (хранятся 5 последних), поэтому переключение обратимо.
- Пользователи, пароли, права и активные сессии находятся в `access.db`, поэтому
  переключение версии расписания их не откатывает и не выбрасывает сотрудников.
- После переключения ранее сохранённые команды переноса остаются историей, но
  адресная отмена для них блокируется: они относятся к другому поколению данных.
- Гостевая страница берёт данные из `public/public_db.json` и обновится только
  после кнопки «Опубликовать».

**Перенос между устройствами.** «⬇» в строке версии выгружает её одним файлом
`schedule-<дата_время>.db`; «⬆ Загрузить файл» принимает такой файл на другом
устройстве. Примечание и исходная дата едут внутри файла, поэтому версия
встаёт в список со своей датой, а не датой загрузки. Загруженный файл
проверяется до появления в списке (должна быть база SQLite с таблицами
расписания) и никогда не помечается автоснимком — иначе автоочистка могла бы
стереть привезённое.

Это дополняет `npm run backup` (снимок всего проекта, включая `access.db`) —
архив из админки хранит только расписание и не является резервной копией
учётных записей.

## Технические заметки

- БД — встроенный `node:sqlite` (Node ≥ 22), без нативной сборки.
- Кодировка HTML — UTF-8 с возможными «битыми» байтами; декодер выбирает вариант
  с меньшим числом символов-замен.
- Даты строятся ИСКЛЮЧИТЕЛЬНО из настройки семестра (парсинг дат из HTML удалён).
- Дизайн-система — общие токены в `public/css/theme.css` (см. .claude-rules.md §3),
  тема через класс `.dark`, без хардкода цветов.
