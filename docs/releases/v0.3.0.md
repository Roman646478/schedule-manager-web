# v0.3.0 — Пользователи, права доступа и печать

## Основные изменения

- Добавлены учётные записи сотрудников с доступом по кафедрам и отдельным группам. Администратор управляет пользователями, паролями и блокировкой.
- Пользователи видят всё рабочее расписание, но редактируют только разрешённые группы; поток с чужой группой защищён целиком.
- Пользователи, права и сессии вынесены в отдельную базу `access.db`: восстановление архива расписания их не откатывает.
- Общий журнал переносов показывает автора и позволяет отменять выбранное действие. Проверки ревизий защищают от устаревших правок, а повтор сетевого запроса не дублирует перенос.
- Гостевой режим предназначен только для просмотра опубликованного расписания.
- Печать получила выбор ориентации и размещение таблицы на заданной сетке листов, повтор служебных столбцов и настройку отображения преподавателей.
- Исправлено отображение дат семестровой сетки: даты идут горизонтально по неделям.
- Исправлена обработка кириллических имён файлов при импорте HTML и Excel.
- Поздний ответ распознавания файлов больше не стирает сообщение о завершённом импорте.
- Добавлена отдельная веб-сборка с номером версии и контрольными суммами файлов.

## Установка

1. Распакуйте `schedule-manager-web-v0.3.0.zip`.
2. Установите Node.js 22 или новее.
3. В папке приложения выполните `npm ci --omit=dev`, затем `npm start`.
4. Откройте адрес, который напечатает сервер. По умолчанию: `http://127.0.0.1:443`.

Это серверное веб-приложение Node.js; архив не содержит Windows-виджет,
рабочие базы, пароли, сертификаты и опубликованный снимок расписания.
Зависимости устанавливаются отдельно. GitHub Releases хранит версии приложения;
для работы сайта нужен запущенный сервер.

## Обновление существующей установки

Перед обновлением остановите сервер и сохраните копию папки `data/`.
Распакуйте новый выпуск отдельно, перенесите `data/` и свои настройки окружения,
установите зависимости и запустите сервер. Миграции выполняются при запуске.
Для полного восстановления сохраняйте обе базы: `schedule.db` и `access.db`.
Встроенные архивы расписания не содержат учётных записей.

На новой установке смените стандартные пароли. Для работы в общей сети
включите HTTPS по инструкции в README.
