## Результаты аудита (кратко)

Без находок (сделано корректно изначально):

- **SQL-инъекции** — везде prepared statements `node:sqlite` с `?`-параметрами;
  имена таблиц/колонок — литералы либо белый список (`getOrCreate`,
  `setEntityHidden`).
- **XSS** — весь вывод данных расписания экранируется `esc()` (`& < > " '`),
  усилено строгим CSP `script-src 'self'`.
- **Контроль доступа** — все роуты данных/мутаций под `requireAuth`; IDOR
  неприменим (единственный администратор).
- **Forced browsing** — секреты (`config.json`) вне `public/`; обработчик ошибок
  не утекает детали.
- **Согласованность 3 представлений** — атомарные транзакции + `validateMove`.

Найдено и исправлено — ниже.

## 1. High — дефолтные пароли без возможности смены

**Проблема.** Учётка `admin/admin` и пароль очистки БД `2707` зашиты как дефолты,
а в работающем приложении не было способа их сменить (`changePassword`/
`changeResetPassword` существовали, но не были подключены к роутам). При
`HOST=0.0.0.0` любой в LAN входил как admin/admin.

**Исправление.**

- `src/services/authService.js` — добавлен `usingDefaultCredentials()`
  (bcrypt-сравнение текущих хэшей с дефолтами); экспортирован.
- `src/routes/auth.js` — новые роуты под `requireAuth`:
  - `POST /api/password` — смена пароля входа (нужен текущий пароль, минимум
    8 символов, запрет совпадения с текущим).
  - `POST /api/reset-password` — смена пароля очистки БД (нужен текущий, минимум
    4 символа).
  - `GET /api/auth/check` теперь отдаёт вошедшему админу флаги `usingDefaults`
    (анониму не отдаются).
- `src/server.js` — предупреждение в консоль при старте, если активны дефолты.
- `public/admin.html` — кнопка **«Сменить пароль»** + модальное окно (выбор:
  пароль входа / пароль очистки; текущий + новый ×2).
- `public/js/admin.js` — обработчик смены; красный баннер вверху админки
  «Используется пароль по умолчанию» с кнопкой смены, исчезает после смены обоих.

## 2. Medium — трафик по LAN без шифрования (нет HTTPS)

**Проблема.** Сервер работал только по HTTP — логин и cookie сессии шли по сети
открытым текстом; флаг `secure` у cookie зависел лишь от `NODE_ENV`.

**Исправление (без новых зависимостей).**

- `src/server.js` — при наличии пары ключ+сертификат сервер автоматически
  поднимается по **HTTPS** (`https.createServer`); иначе HTTP с предупреждением.
  Флаг cookie `secure` привязан к реальной защищённости соединения (HTTPS или
  доверенный прокси). Опциональный порт **HTTP→HTTPS-редиректа**.
- `src/utils/constants.js` — `TLS_KEY_PATH`/`TLS_CERT_PATH` (по умолчанию
  `data/tls/`), `HTTP_REDIRECT_PORT`, `HSTS_ENABLED`.
- **HSTS** по умолчанию выключен — несовместим с самоподписанным сертификатом
  (закрыл бы доступ); включается осознанно через `HSTS_ENABLED=1`.
- `scripts/generate-cert.js` + npm-скрипт **`gen-cert`** — офлайн-генерация
  самоподписанного сертификата через системный `openssl`, с автоматическим
  вписыванием всех LAN-IP машины в SAN (подходит для доступа по сетевому адресу).
- `README.md` — раздел «HTTPS в локальной сети».

Включение оператором: `npm run gen-cert` → `npm start` (сервер сам перейдёт на
HTTPS).

## 3. Low — CSRF-защита

**Проблема.** Мутации защищались только `sameSite=lax` + тем, что `express.json`
принимает лишь `application/json`. Токена не было.

**Исправление (double-submit token).**

- `src/middleware/csrf.js` — токен в сессии; для небезопасных методов обязателен
  заголовок `X-CSRF-Token`, сверяется через `timingSafeEqual`.
- `src/server.js` — `GET /api/csrf` (выдача токена) + `app.use('/api',
  csrfProtection)` перед роутами. `/login` исключён (сам устанавливает сессию).
- `public/js/api.js` — токен запрашивается лениво, кэшируется и подставляется во
  все мутации (включая `upload`); при `403 CSRF` — один автоповтор с обновлением
  токена. Все страницы ходят через `api.js`, поэтому покрыты разом.

## 4. Low — харднинг импорта (DoS / тип файла)

**Проблема.** `multer` принимал до 200 файлов × 5 МБ в память (~1 ГБ) без
проверки типа.

**Исправление.**

- `src/routes/import.js` — лимит на файл **5 МБ → 2 МБ**, число файлов
  **200 → 120** (потолок памяти ~240 МБ); `fileFilter` принимает только HTML
  (по расширению/MIME); ошибки multer (превышение размера/числа) → понятный
  **400** вместо 500.

## 5. Осознанно без изменений

- **Rate-limit логина** — уже реализован (10 попыток/15 мин на IP), для
  изолированной LAN достаточен.
- **Длительность сессии 30 дней** — намеренное UX-решение, настраивается через
  `SESSION_MAX_AGE_MS`. Дефолт не меняли.
